# Paper → code mapping

Maps the ISSRE 2026 paper *"What SLA Can I Commit To?"* to slacheck modules. **The single source of
truth for the paper is `issre_paper.tex`** (+ `refs.bib`, `figures/`); it presents *one unified
method* — the **full method** — and uses an **ablated baseline** (series aggregation, uniform
decomposition, no reconfiguration model) only as a comparison point in the evaluation.

In the **code**, those two configurations are selectable via `--paper-version v1|v2` (default `v1`).
This is a code flag, **not** two separate papers:

- **v1 = the ablated baseline**: series-only aggregation, uniform decomposition. Its exact worked
  numbers are the **frozen regression contract** — never change v1 code/tests.
- **v2 = the full method**: typed DAG, topology-sensitive operators (incl. disjunctive redundancy),
  safety margins → A_commit, structural-weight decomposition, and reconfiguration sustainability.

slacheck sources the topology from live Datadog (see `datadog_api_catalog.md`) and presents the
result as a Datadog dashboard.

> **Naming note.** The paper says "baseline / full method"; the code says "v1 / v2". They denote the
> same two configurations — v1 is simply the configuration the evaluation ablates down to. The table
> below keeps the "v1 / v2" split because it documents the *code*; the paper's `tab:eval` is
> regenerated verbatim by `slacheck eval --both --latex` (columns **Baseline / Full**, with the
> Total row). Paper figures are generated by `scripts/gen_figures.py` into `figures/` from the same
> code paths as the tables (no hardcoded numbers).
>
> **Evaluation scripts (each paper number == a script's output):**
> - `gen_eval.py` / `eval/runner.py` → Table I (constructed dataset, 113/67).
> - `case_study.py`, `multi_system_study.py` → §V-B real systems (train-ticket, Online Boutique).
> - `gen_realistic_eval.py` (modes `window`/`indep`, position param) + `realistic_study.py` → §V-C
>   headline (89.5% vs 4.0%, Fig. detection_realistic).
> - `sweep_study.py` → §V-C position sweep (Fig. detection_sweep) — defuses the "tautology" critique.
> - `indep_study.py` → §V-C independent-distribution rate (100% vs 89.0%, unconstructed measurement).
> - `gamma_study.py` → §III-B safety-margin sensitivity (Fig. gamma_sensitivity, A* = 99.70%).
>
> The live Datadog loop has been exercised end-to-end (topology discovery, live latencies, dashboard
> publication — paper §IV); `docs/live_unblock.md` is the runbook for pointing it at another org.

### v1 worked example (regression contract, §II + §IV)
Three components UI/Auth/Stor, each 99.9% availability → envelope `100 − 3×0.1 = 99.7%`; target
99.999% → ascending fault; cost 23 ÷ 3 ≈ 7.67 per component. (`tests/test_operators.py`,
`tests/test_aggregate.py`, `tests/test_faults.py`, `tests/test_decompose.py`.)

## Part B — v2 = the full method (the paper's contributions)

| v2 (full-method) concept | Section | Code |
|---|---|---|

### v2 worked numbers (proven in tests)
- conjunctive availability of three 99.9% = **99.7%** (== v1); disjunctive of two 99.9% = **99.9999%**.
- running case in-degrees → weights **wUI=1/5, wAuth=wStor=2/5**; cost T=23 → **sUI=4.6,
  sAuth=sStor=9.2** (vs uniform 7.67).
- margins (tier2=0.01, tier3=0.05) → **A_commit 99.59% < A\* 99.7%**; 99.999% target faults vs A_commit.
- **Table I**: v2 = 10/10, 60/60, 43/43; v1 = 10/10, **57/60**, 0/43 — the 3 v1 misses are exactly the
  heterogeneous-consumption `sub_gap` cases, closed by weighted decomposition.
  (`tests/test_operators_v2.py`, `test_decompose_v2.py`, `test_margins_v2.py`, `test_eval_table1.py`.)

> **Honesty note on the evaluation dataset.** `fixtures/eval/` is a **constructed** dataset
> (generated by `scripts/gen_eval.py`) that demonstrates the *mechanism* by which v2 improves on
> v1 — it is **not** an empirical benchmark over diverse real systems. The category counts (10/60/43)
> mirror the paper. The Sub-SLO cases are diversified (varied size/metric/values) and each scenario
> names the *specific* injected fault (metric + component + direction), so the harness checks the
> right fault is detected — not just any fault of that metric. The headline result is that v2's
> weighted decomposition closes the 3 faults uniform decomposition structurally misses.

## Extensions beyond both papers (the internship engineering contribution)

1. **Live topology** from Datadog APM instead of hand-written YAML.
2. **Critical-path extraction** (v1) / **typed-DAG projection** (v2) on a real branching topology.
3. **Datadog dashboard** as the output surface (the papers just print to stdout).
4. **Kubernetes resource enrichment** (CPU/mem/restarts per service) — a live signal available even
   when APM tracing is not.
